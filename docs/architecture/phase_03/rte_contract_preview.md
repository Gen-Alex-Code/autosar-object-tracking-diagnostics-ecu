# RTE Contract Preview

**Project:** `autosar-object-tracking-diagnostics-ecu`  
**Phase:** 3 — SWC Architecture  
**Status:** Draft v3

---

## 1. Purpose

This document previews the generated-style RTE access functions expected by the two-SWC architecture.

The actual implementation will be manual and educational, but the API style shall resemble generated AUTOSAR RTE access.

---

## 2. RTE Contract Honesty Statement

The functions shown here are not generated by a production AUTOSAR tool.

They are manually implemented generated-style interfaces used to emulate how application SWCs depend on an RTE contract rather than direct infrastructure calls.

## 7. Header Mapping

Expected generated-style headers:

```text
include/generated/rte/Rte.hpp
include/generated/rte/Rte_Types.hpp
include/generated/rte/Rte_SensorInputSWC.hpp
include/generated/rte/Rte_ObjectTrackerSWC.hpp

```

---

## 8. Implementation Rule

Application SWC implementation shall include only its generated-style RTE contract header.

It shall not include DEM, DCM, NvM, COM, OS, GPIO, or driver headers directly.
